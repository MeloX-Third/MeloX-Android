# 音乐源解耦与迁移计划

目标是让宿主通过 `SourceId` 和能力接口调用音源。用户可以在弥乐内安装、启用、禁用、更新、卸载和重装可选音源。每个迁出的音源需要达到原有功能的验收标准。

## 交付约定

所有音源统一沿用 `melox-unm-resolver` 的交付和导入流程。每个音源拥有独立仓库、版本、许可证和 Release，构建产物为 `<source>-<version>.melox-plugin`，由「设置 → 音乐源插件」导入和管理。包包含 `manifest.json`、JavaScript 入口和 `integrity.json`，通过现有 SDK 打包。参考项目提供包结构、构建和安装示例，音源按实际支持的能力声明搜索、播放、歌词、歌单等接口。[参考插件](https://github.com/MeloX-Third/melox-unm-resolver)

宿主负责来源注册、原生通用界面、播放器、受控网络、系统权限和账号凭据隔离。平台接口、登录协议适配、数据映射、音质规则和专属业务逻辑由各音源插件实现。登录回调、原生媒体和设备访问遇到 SDK 缺口时，先补齐通用宿主能力及协议，再完成对应插件的迁移。验收时，在同一宿主版本上通过插件管理页验证每个音源的导入、启用、更新、停用和卸载。`.melox-plugin` 是音源唯一的交付格式，伴生 APK 不纳入迁移和发布方案。

各插件按自己的许可证独立分发，并提供适用的第三方声明及源码链接。接入外部服务时，按该服务的使用条款确认发布要求。

## 执行顺序

1. **统一来源查找。** 将注册表按 `SourceId` 索引，旧 `MusicSource` 接口委托给同一查找路径。保留内置枚举的存储值，逐步将聚合搜索、播放、歌词和音乐库调用切换到稳定身份。
2. **补齐操作能力。** 依次接入歌单创建、改名、删除、歌曲移除和排序。每项可独立声明。排序和删除歌曲需要区分歌单成员与歌曲 ID，覆盖重复歌曲。核对收藏、账号、下载、评论、云盘、播客、私信和一起听，按平台记录实际支持的操作和对应入口。
3. **把平台逻辑移到插件。** 将会话状态、缓存指纹、音质规则、目录映射、服务中心入口和错误处理交给插件。宿主提供媒体会话、下载、离线播放和通用页面。系统媒体访问、设备授权、本地文件及原生播放由宿主通过受控的通用接口提供，保持媒体授权和凭据隔离。
4. **建立内置音源迁移路径。** 按音源建立旧来源和新实现的可信绑定，资源 ID 保持稳定。迁移覆盖收藏、历史、队列、歌词绑定、下载文件和索引、推荐与当前音源。迁移须可重试，先验证备份与回滚，再切换写入。凭据留在宿主管理的账号存储中。无法安全迁移的账号通过重新授权恢复。
5. **分批切换。** 用 CC0 示例验证插件安装流程，按下表逐个迁移首批七个音源。酷我、Jellyfin、Apple Music、本地音乐等后续来源沿用同一交付方式。保留旧酷狗来源兼容。每个音源通过功能等价和数据迁移验收后再切换旧入口。
6. **验证发布。** 运行 SDK、Android 单元测试、构建和设备测试。覆盖 API 24 与当前支持版本、冷启动、后台和熄屏播放、断网、下载续传、切换账号、升级回滚、同身份卸载重装、不同发布者与权限变化。旧版 APK 往返使用独立测试数据，检查收藏、历史、队列和下载的一致性。

宿主移出平台实现后仍须能构建、启动、识别旧资源和访问已有下载。下列七个音源各交付一个独立的 `.melox-plugin`，保留通用能力和平台专属功能。

## 新增音源

- **飞牛音乐（#134）**以 `.melox-plugin` 交付，支持用户填写 NAS 地址直连。宿主补齐通用的局域网授权，将用户明确批准的访问绑定到插件及目标地址、端口，并对 API、封面和音频使用同一授权边界。服务器配置、登录适配、曲库、歌单、搜索、播放解析和歌词由插件负责。
- **NekoMusic（#129）**以独立 `.melox-plugin` 交付，采用自己的 AGPL-3.0 许可证。首版范围为访客搜索、封面、播放和歌词，账号能力单独接入。发布前按上游条款确认独立插件的接入范围，并提供规定的署名、源码和 API 文档链接。

## 卸载重装验收

- 默认保留资源身份、用户记录、已下载文件和索引、账号和普通存储。显式清除的数据需在确认界面列明。
- 插件缺失时显示原有歌曲与缺失状态，保留本地已下载内容可访问的路径。同身份兼容包重装并启用后恢复在线操作。
- 禁用、卸载或切换账号后，旧请求的结果不得绑定到新会话。正在播放或下载的任务按宿主生命周期策略处理。
- 用旧版本创建一组真实记录，迁移后按条目比对，再循环安装、禁用、卸载和重装。验证切换失败能恢复旧实现且记录完整。

每项功能独立提交，实现、必要的测试和协议变更放在同一次提交中。现有 `playlistWrite` 是歌单追加操作的基础。同一来源卸载重装已有注册表回归用例，账户、离线及实际设备恢复仍需验收。

## 当前进度

- 注册表已按 `SourceId` 查找，支持仅有已安装插件的情况。推荐聚合从注册表获取来源，目录页使用通用 Provider 能力接口。播放缓存由注册表提供各来源的会话指纹。
- 插件已接入歌单追加、创建、改名、删除、按成员移除，以及同页排序。CC0 示例 1.2.0 覆盖重复成员和旧示例存储升级。
- `:music-provider-api` 的共享模型和能力接口可继续用于宿主解耦。首批七个音源的独立 `.melox-plugin` 仍待迁移和交付。
- 此前已通过 15 项 SDK 测试和 21 项独立 JVM 测试。Android CI 已加入迁移相关用例。卸载重装存储、歌单编辑和酷我账号槽位的设备用例等待设备运行。

## 酷我 APK 试点记录

`:provider-kuwo-apk` 和 `:music-provider-service` 曾用于验证搜索、歌词和播放解析的跨进程接入，产出了 Debug APK。该分发路线已停止。后续将酷我迁入 `.melox-plugin`，验证旧数据迁移和功能等价后收尾试点安装入口及专用 IPC。通用 `SourceId`、能力接口和注册表继续用于插件迁移。
